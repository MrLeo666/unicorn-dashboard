# Unicorn Dashboard — Deployable Sub-Project

Self-hosted version of the unicorn bubble dashboard. Wikipedia is the only auto-scraped source; PitchBook data is frozen at the initial seed. You can manually edit any record (including adding new companies, fixing Chinese names, deleting bad entries) through `admin.html`, which exports an `overrides.json` file that you commit to the repo.

## Folder structure

```
deploy/
├── index.html                  # public dashboard (fetches data/unicorns.json at runtime)
├── admin.html                  # local-only admin page (edit + export overrides.json)
├── data/
│   ├── unicorns.json           # ✱ the merged dataset the dashboard renders
│   ├── wiki_raw.json           # ✱ fresh Wikipedia scrape (auto-updated weekly)
│   ├── seed_pitchbook.json     # frozen PitchBook-only rows from the initial seed
│   ├── chinese_names.json      # manual mapping: English → {zh, pinyin}
│   └── overrides.json          # admin-page exported edits/additions/deletions
├── scripts/
│   ├── scrape_wikipedia.py     # HTTP + BeautifulSoup; rebuilds wiki_raw.json
│   ├── merge.py                # wiki + seed_pitchbook + chinese_names + overrides → unicorns.json
│   └── requirements.txt
├── .github/workflows/
│   └── update-data.yml         # weekly cron + manual trigger
└── README.md
```

✱ = auto-generated by scripts.

## Deploy in 5 minutes (GitHub Pages)

1. **Create a new GitHub repository** (any name, e.g. `unicorn-dashboard`). Public is free; private needs Pro.
2. **Copy the contents of this `deploy/` folder** into the repo root and push:
   ```bash
   git init
   git add .
   git commit -m "init unicorn dashboard"
   git branch -M main
   git remote add origin git@github.com:<your-username>/unicorn-dashboard.git
   git push -u origin main
   ```
3. **Turn on GitHub Pages**: Repository → Settings → Pages → Source = `Deploy from a branch`, Branch = `main` / `/ (root)`. Wait ~1–2 minutes.
4. **Visit your dashboard**: `https://<your-username>.github.io/unicorn-dashboard/`.
5. **Verify the auto-update**: Repository → Actions → "Update unicorn data" → Run workflow. After ~30 seconds, check that `data/unicorns.json` has been regenerated.

That's it. The dashboard now updates itself every Monday at 08:00 UTC (16:00 Beijing).

### Custom domain (optional)

Add a `CNAME` file at the repo root with your domain (e.g. `unicorns.example.com`), and add a CNAME DNS record pointing to `<your-username>.github.io`.

## How the data pipeline works

```
            ┌──────────────────────┐
weekly job  │ scrape_wikipedia.py  │ ──→ data/wiki_raw.json
            └──────────────────────┘
                       │
                       ▼
             ┌──────────────────┐
             │   merge.py       │
             │                  │
             │ inputs:          │
             │  · wiki_raw      │
             │  · seed_pb       │   (frozen, never re-scraped)
             │  · chinese_names │   (manual edits to this file)
             │  · overrides     │   (admin.html exports)
             └──────────────────┘
                       │
                       ▼
             data/unicorns.json  ◀──── the dashboard fetches this
```

The merge order is **Wikipedia → frozen PitchBook seed → Chinese names → admin overrides**. Anything later wins on conflict.

## Editing data manually (admin.html)

The admin page is a static HTML file you load locally or from your deployment URL. **All edits live in your browser's localStorage until you click Export.** Nothing is sent to a server.

1. **Open `admin.html`** — either locally (you'll need to serve via `python3 -m http.server 8080` or similar so `fetch()` works), or by visiting `https://<your-username>.github.io/unicorn-dashboard/admin.html`.
2. **Search / filter** to find a company. The "Edited / Added / Deleted / Chinese only" pills filter the table.
3. **Edit** any row → modal with all fields. Save commits the change to localStorage and marks the row blue.
4. **Add a new company** → top-left button. Choose to fill any subset of fields.
5. **Delete a row** → marks for removal (the row goes grey/strikethrough). Click again to undelete.
6. **Export** → downloads `overrides.json`. Drop the file into your repo's `data/` folder and `git push`. The next merge run will apply it.
7. **Import** an existing `overrides.json` → loads someone else's edits (e.g. you collaborating with a teammate, or rolling back to a checkpoint).

A live JSON preview at the bottom shows exactly what will be exported.

### Override file format

```json
{
  "edits": {
    "Talent": {
      "companyZh": "蜂巢能源",
      "pinyinInitial": "F"
    }
  },
  "additions": [
    {
      "company": "NewCo",
      "companyZh": "新公司",
      "pinyinInitial": "X",
      "valuation_m": 5000,
      "valuation_str": "$5B",
      "country": "China",
      "industry": "AI/ML",
      "description": "...",
      "wikiLink": ""
    }
  ],
  "deletions": ["BadCompany"]
}
```

`edits` keys are the **English company name** as it appears in `unicorns.json`. Only changed fields need to be specified — unchanged fields fall through to the source row.

## Manual maintenance: Chinese names

`data/chinese_names.json` is the master mapping from English → Chinese. The format:

```json
{
  "ByteDance":  { "zh": "字节跳动", "pinyin": "Z" },
  "DJI":        { "zh": "大疆",     "pinyin": "D" }
}
```

Edit this file directly when you want a permanent mapping that survives across all admin-override resets. It's keyed on the English name and only applies to companies whose `country` contains "China" or "Hong Kong".

The weekly Action does NOT modify this file — only humans do.

## Common operations

**Run a one-off update locally:**
```bash
cd deploy
pip install -r scripts/requirements.txt
python scripts/scrape_wikipedia.py
python scripts/merge.py
python3 -m http.server 8080         # then open http://localhost:8080/
```

**Force a refresh on the live site without waiting for cron:** Actions tab → "Update unicorn data" → "Run workflow" → main.

**Add a Chinese name for a newly-found company:**
- Quick fix: open `admin.html`, edit the row, export `overrides.json`, commit.
- Permanent fix: edit `data/chinese_names.json` and commit.

**Roll back a bad merge:** revert the auto-commit in your repo's history, or use the admin page's "Reset all changes" button if the bad data lives in your local edits.

## Privacy & costs

- **Free** for public repos: GitHub Pages bandwidth + Actions minutes (~30s/week, well under the 2000 min/month free tier).
- **Private repo**: GitHub Pro ($5/mo) or move to Cloudflare Pages (free for private too).
- **No backend**, no database, no API keys needed.
- Admin edits never leave your browser unless you explicitly Export and commit.

## Watch-outs

- Wikipedia's table structure occasionally changes. The scraper looks for the table whose header contains "Company", "Valuation", and "Founder" — if their schema diverges from this, the script will fail loudly. Check Actions logs.
- Wikipedia values are user-contributed; a recently updated valuation may be wrong. Use admin overrides to correct in one place.
- The initial seed (`seed_pitchbook.json`) is frozen May 2026. If a PitchBook-only company exits / gets acquired / goes public, you'll need to delete it via admin overrides.
- Chinese name mappings are best-effort; some entries are marked `(?)`. Look at `chinese_names.json` and clean them up as you have time.

## Tech stack

Vanilla HTML + Canvas2D + D3 v7 for the dashboard. No build step, no npm. Python 3.11 + requests + BeautifulSoup for the scraper. GitHub Actions for cron. Total dependencies: ~6 packages.
